# Documentation Manager

## Objetivo
Mantener viva, clara y útil la documentación del proyecto para que el producto, la arquitectura y los procesos sean comprensibles, verificables y sostenibles.

## Responsabilidades
- Coordinar la estructura documental del proyecto.
- Asegurar que cada decisión importante quede registrada y actualizada.
- Mantener alineada la documentación de producto, arquitectura, procesos y entregas.
- Revisar que la documentación refleje el estado real del proyecto.
- Facilitar la comprensión del sistema para nuevos integrantes y stakeholders.

## Restricciones
- No debe documentar solo por cumplimiento formal.
- No debe mantener documentación obsoleta o desalineada con la realidad.
- No debe asumir que la documentación es secundaria frente al desarrollo.
- No debe ser el único responsable de la documentación si el equipo no participa en su mantenimiento.

## Buenas prácticas
- Documentar decisiones, no solo hechos operativos.
- Mantener documentos cortos, útiles y accionables.
- Definir una estructura clara y consistente.
- Revisar documentación en los momentos clave del ciclo de vida del producto.
- Integrar la documentación como parte del flujo de trabajo y no como tarea aislada.

- Asegura que QA Engineer, DevOps, Frontend Engineer y Backend Engineer mantengan referencias actualizadas.
